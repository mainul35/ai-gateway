Connect an AI Agent

Coding agents can use this gateway's models with one of your API keys. Use a model that can call tools (the list above says tools), and tell the agent its real context size.

Applications — start an agent on one of these models

1Install the launcher — once per computer. It asks for your API key the first time (or reads AI_GATEWAY_API_KEY) and can keep it for next time.

2Start an app on a model, in the folder you want to work in.

Each app is pointed at this gateway in a place of its own, so the way you use it otherwise is untouched: Claude Code in ~/.claude-gateway, Hermes in ~/.hermes-gateway; OpenCode, Qwen Code and Codex for that one run only. OpenClaw keeps one config, so an ai-gateway provider is added to it (backed up first). An app that is not installed is not installed for you: the launcher prints its install command. Add --config to set an app up without starting it, and anything after -- goes to the app as typed. ai-gateway models lists what you may use. Claude Code, OpenCode and Codex also get Your projects as tools: they can search and read your other repositories and share notes across workspaces. Qwen Code does not yet.

Does not affect Claude Desktop. This config is for the Claude Code CLI only (the terminal agent in your terminal). It does not affect the Claude desktop app (the GUI app you open from your Applications folder). They are two completely separate applications.

If you are signed in to claude.ai, run /status in Claude Code: it should name the auth token, not your claude.ai account. If it names the account, use the launcher, or start Claude Code with CLAUDE_CONFIG_DIR pointing at a separate folder.

Claude desktop app — the GUI application (macOS / Windows)

Completely separate from Claude Code CLI. The config above (in .claude/settings.local.json) has zero effect on this app. Claude Desktop is Claude.ai's own GUI — it uses its own config files, not Claude Code's.

Automatically: the launcher command above, ai-gateway launch claude-desktop, does everything below for you: it writes an AI Gateway profile into the app's settings and makes it the one in use, then closes the app (also from the tray) and opens it again. Its model picker then lists this gateway's models under Claude's names - Sonnet, Opus, Haiku and Fable all run qwen3.6-256k, which also reads images, so a picture never swaps models mid-task, and Sonnet 4.6 runs auto. The second command, with -Restore (--restore on macOS and Linux), puts the app back on your Claude account.

By hand, if you would rather click: Help → Troubleshooting → Enable Developer Mode, then Developer → Configure Third-Party Inference:

  • Inference provider: Gateway
  • Gateway base URL:
  • Gateway API key: one of your keys, auth scheme Bearer
  • Models: leave the list empty and the app asks the gateway, as above. To add one of your own, the app accepts only names that look like Claude's: write claude- and the gateway model's name with : and . as -, and put the real name in Display name - claude-gemma4-31b is gemma4:31b, claude-qwen3-next-80b is qwen3-next-80b (text only).
  • Offer 1M-context variant: turn it on for projects bigger than 256K tokens. The 1M choice runs qwen3.6-1m, which is slower at every length, so use it only when the conversation needs it.

Either way, this moves every desktop session — Code and Cowork — to this gateway, and Remote Control and cloud sessions are unavailable while it is on. To keep the desktop app on Claude, use Claude Code through the launcher instead.
